    02Positioning

    Burp Suite stays the engine. The phone becomes the console.

    Burp Remote is a remote-control framework for Burp Suite aimed at red teamers and security researchers. It carries three Burp workflows — proxy history, the intercept queue and Repeater — onto an Android phone, so the assessment does not stop when you step away from the machine. All computation stays inside Burp; the phone issues commands and renders results.

    03Architecture

    One event stream, one sequence, one snapshot fallback.

    Proxy observations, intercept decisions and Repeater actions are all stamped with a monotonically increasing sequence number and pushed over WebSocket. Sequence numbers are allocated centrally by InMemoryRemoteEventStream — the history, intercept and Repeater publishers share a single AtomicLong. Independent counters previously collided, causing the mobile sync coordinator to treat live events as duplicates and drop them silently.

    Connection lifecycle

    Disconnection is symmetric. The client sends a WebSocket Close frame wrapped in NonCancellable so delivery cannot be abandoned mid-flight, while the plugin concurrently reads incoming frames to notice it immediately — tearing down the session, releasing the connection slot and disassociating the device without waiting for the 30-second ping timeout.

    06Protocol Reference

    Sixteen REST endpoints and one WebSocket stream.

    The extension serves REST on http://<your-IP>:9000 and pushes events on ws://<your-IP>:9000/v1/events.

    07Pairing

    Scan once, stay registered.

    1. 01

      Load the extension JAR — it listens on 0.0.0.0:9000.

    2. 02

      Open the Burp Remote tab in Burp to read the QR code and pairing code.

    3. 03

      Install the APK, then scan the QR code or type the code manually.

    4. 04

      Connected — events begin syncing immediately.

    The pairing code is 8 characters and valid for 5 minutes, drawn from a confusable-free alphabet with no I/O/0/1/L/U. One scan registers the device identity, so reconnecting never requires another scan.

    09Theme System

    Mode sets the luminance. Flavour sets the character.

    Light/dark mode and flavour are orthogonal: the mode controls base luminance, the flavour controls accent and tone. There are three modes — follow system, light, dark — crossed with eight flavours.

    Semantic colours (success, warning, error, info) and syntax highlighting stay constant across every flavour. The bottom navigation bar uses Haze real-time blur with a translucent surface, a top highlight gradient, a bottom inner shadow and elevation — tuned separately for light and dark.

    10Quick Start

    Two scripts, two artefacts.

    Requirements

    • JDK 17 — Burp 2025.x runs on 17, and higher bytecode is rejected at load time.
    • Burp Suite Community or Professional, 2025.x or later.
    • An Android device on API 26 (Android 8.0) or above.
    • Both devices on the same LAN — the extension listens on 0.0.0.0:9000 by default.

    Both scripts accept JAVA_HOME_FOR_BUILD to point at JDK 17 and pass extra arguments through to Gradle. Load the JAR via Extensions → Installed → Add → Java.

    Release

    Pushing a tag triggers GitHub Actions, which builds the JAR through the quality gates and the APK on JDK 17, then attaches both to a GitHub Release.
